\section{Requirement Analysis}
\label{sec:requirement_analysis}

Requirements were gathered by examining the functional responsibilities of each system module. Since this is a simulation platform rather than a client-commissioned product, requirements were derived from the project's own objectives: what the agents need to do, what the dashboard needs to display, and what data needs to be persisted.

\section{Feasibility Study}
\label{sec:feasibility_study}

\subsection{Technical Feasibility}

All technologies used in this project are open-source and freely available. Python, FastAPI, React, SQLite, and scikit-learn have well-documented APIs and active community support. The Google Gemini API provides a free tier sufficient for the expected volume of calls in a simulation environment. The project does not require specialized hardware---a standard development laptop with 8GB RAM is sufficient to run the backend, frontend, and ML training pipeline concurrently.

\subsection{Operational Feasibility}

The system is designed for single-operator use or small team operation. The React dashboard provides a visual interface that does not require command-line expertise. Simulation runs are triggered with a button click, and results are displayed automatically. PDF and CSV exports are one-click operations. The learning curve is minimal.

\subsection{Economic Feasibility}

The project has zero licensing costs. Python, Node.js, SQLite, React, Leaflet, and scikit-learn are all open source. The Gemini API free tier covers the project's needs. Hosting the application requires only a standard web server. No cloud-specific infrastructure (containers, load balancers, managed databases) is required for development and demonstration purposes.

\subsection{Schedule Feasibility}

The project was developed over a single academic semester. The modular architecture allowed parallel development of independent components: the ML pipeline was developed alongside the frontend, and the route optimization module was built independently of the agent framework. This parallelism kept the project on schedule.

\section{Chapter Summary}
\label{sec:ch4_summary}

This chapter documented 15 functional requirements and 8 non-functional requirements derived from the project's modules. The feasibility study confirmed that the project is viable across technical, operational, economic, and schedule dimensions. Software dependencies include Python 3.10+, Node.js 16+, FastAPI, React 18, SQLite, scikit-learn, Leaflet, and ReportLab. The hardware requirements are modest, with the system running comfortably on a standard development machine.
